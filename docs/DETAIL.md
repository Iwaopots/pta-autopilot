# PTA 作业 · 多账号

把 PTA（pintia.cn）的作业流程搬进 DSH：账号、题面、提交、判题都在侧栏「PTA 作业」里完成，Agent 只负责读题和写答案。

## 它解决什么

- **多个 PTA 账号**：一个账号一条凭据记录，互不干扰；面板里能加、校验、设默认、删。
- **Cookie 不进对话**：PTASession 在受保护页面粘贴，直接写进 DSH 凭据服务；Agent 只看到账号 id 和昵称。
- **省 token 的读题**：题目拉一次落盘，读题用一行一道的压缩视图，不把整份 JSON 塞进上下文。
- **一次答准**：客观题整卷提交、提交前可先给用户过目；编程题提交后自动轮询判题，看失败用例再改。

## 第一次用

1. 侧栏点「PTA 作业」，账号栏点「添加」。
2. 默认「账号密码」登录（要滑块时点「滑块后登录」）；也可以切「粘贴 Cookie」贴 `PTASession`。
3. 校验通过显示「已登录」，中间栏自动加载各题目集完成度。

## 日常

- **一键完成**：中间栏某个题目集点「一键完成」，插件自动开一个 Agent 会话开工，右侧队列实时显示进度；「全部完成」一次派发该账号所有未完成题集（考试类自动跳过）。
- **多账号并发**：不同账号同时跑（默认最多 2 个），同一账号串行；临期（2 天内截止）的自动排前面，「插队」可手动提前。
- **失败重试**：会话异常或没收尾会自动退避重试，最多 3 次；失败的任务可点「重试」。
- 当前 DSH 不支持插件开会话时，顶部会显示「需在对话里开工」：派发后对 Agent 说一句「执行 PTA 任务」即可。

## 数据放在哪

`~/.dsh/storages/pta/`：`accounts.json` 只存账号元数据（0600，无 Cookie）；`tasks.json` 是任务队列和操作日志；`work/<账号>/<PSID>/` 存题面、待办和提交过的源码。凭据本体在 DSH 凭据服务里。

## 边界

- 只操作你本人的账号；限时考试类题目集先问你。
- 客观题在截止前平台只显示「已提交」，看不到对错，所以要一次答准。
- 公共题解库的代码原样提交可能被查重，优先自己写。
